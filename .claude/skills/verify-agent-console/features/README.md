# Карта проверки конструктора агентов

Эта папка — поддерживаемый источник сценариев проверки пользовательских функций конструктора агентов (main-node + консоль на русском).
Перед тем как вести приложение, прочитайте этот индекс, затем возьмите файл нужной функции как рецепт.

## Baseline preconditions

- Экземпляр поднят командой `RUN="$(scripts/launch.sh)"`, и `scripts/doctor.sh --run "$RUN"` даёт «ИТОГ: можно вести». Консоль и API доступны на `http://127.0.0.1:8791`. Все скрипты после launch получают прогон явно (`--run` или `VERIFY_RUN_DIR`).
- Папка данных прогона пустая на старте: `~/.cache/verify-agent-console/runs/<RUN_ID>/data`. База SQLite, миграции применены.
- Тестовая учётка создана командой `scripts/seed-user.sh`. Почта, пароль, `user_id` и `tenant_id` лежат в `state/test-user.json` прогона. Почту подтверждает `GET /auth/get-session`: `/v1/oma/me` на main-node отдаёт пустой `email`.
- Режим модели `fake`: фейковая модель на `127.0.0.1:8792`. Режим `real` — только по `VERIFY_MODEL_MODE=real`, если `grep -c '^ANTHROPIC_API_KEY=.' platform/.env` даёт 1.
- Карточек моделей, хранилищ, навыков и MCP-серверов на старте нет.
- Не вести экземпляр, который не был запущен этим прогоном: порты 8787, 8788, 5173, 5174 чужие.

## Driving conventions

- Браузер: Playwright 1.59.1 из `platform/node_modules`. Окно 1280×860, `locale: ru-RU`.
- Chromium выбирается как в `scripts/journey-env-to-agent.mjs` (`pickChromium`).
- Предпочтительные зацепки:
  - роли и подписи: `getByRole("dialog", { name })`, `getByRole("tab", { name })`, `getByLabel`;
  - id полей: `#agent-name`, `#env-name`, `#session-title`;
  - атрибуты `data-*`: `data-testid="data-body-table"`, `data-session-turn-*`, `data-slot`.
  CSS-цепочки и координаты не используются.
- Навигация идёт по ссылкам в `getByRole("navigation", { name: "Разделы консоли" })`: «Агенты», «Сессии», «Окружения», «Хранилища секретов», «Навыки», «Карточки моделей».
- Кнопка создания в пустом списке дублируется (панель и пустое состояние), поэтому берите `.first()`.
- Строки таблиц ищутся по тексту имени: `[data-testid="data-body-table"] tr[data-slot="table-row"]`. Ссылки и `data-id` у строк нет.
- Окна — это Radix Dialog, `role=dialog` с именем из заголовка. Ошибки API показываются тостом в регионе «Уведомления».
- API для сверки вызывается через `context.request` той же сессии браузера, с заголовками `origin` и `anthropic-beta`. Флаги beta те же, что у консоли: `apps/console/src/lib/api.ts:2-10`.
- Каждое создаваемое имя содержит одноразовый `nonce`, чтобы прогоны не путались.

## Proof and skip reporting

- На каждое действие нужны скриншот действия и скриншот результата. Перед снимком ждите содержимое страницы (h1 раздела, строку таблицы или пустое состояние), а не смену URL: клиентский роутер меняет URL раньше, чем перерисовывает страницу. Два подряд одинаковых по sha256 скриншота шагов — провал `evidence.screens_distinct`. Для ключевых экранов дополнительно ARIA-снимок `locator("body").ariaSnapshot()`.
- Оболочка консоли прокручивает `main`, а не документ, поэтому `fullPage` не снимает низ длинной страницы. `shot()` в сценарии на время снимка растягивает окно на высоту внутренней прокрутки (до 6000 px).
- Изменение данных подтверждается вторым способом, только чтением: API (`GET`), файлом в папке прогона или строкой лога.
- Работа песочницы доказывается событиями `agent.tool_use` и `agent.tool_result`, логом BoxLite (`Box started successfully`, `Box stopped`), папкой `.openma/litebox-scratch-*` и ядром VM, которое отличается от ядра хоста.
- Каждая проверка пишется в `summary.md` со статусом «проверено», «провал», «внимание» или «не проверено» и ссылкой на доказательство.
- Недоступный путь записывается со статусом «не проверено». В примечании указываются попытка и недостающее условие. Путь не засчитывается как проверенный через другой вход.

## Feature entry contract

Каждый файл функции начинается с заголовка H1 и абзаца о видимом пользователю поведении. Дальше идут ровно четыре раздела H2 в таком порядке:

1. `Sub-features` — короткие id, по строке на поведение.
2. `How to get to it (user POV)` — все входы пользователя.
3. `Driving it with Playwright (verify-agent-console)` — начинается с `Preconditions:`. Дальше пункты с меткой: действие, точная зацепка или команда и наблюдаемый результат.
4. `Gotchas` — ловушки, из-за которых прогон теряет время или становится недействительным.

## Features

- [Окружения](./environments.md) — создание, карточка (описание, сеть, пакеты), проба песочницы через сессию, архив и удаление. Главный сценарий покрывает создание, карточку с сохранением, пробу и проверку, что пакет и сеть «Ограниченный» действуют в VM.
- [Агенты](./agents.md) — шаблоны, форма, режим YAML/JSON, инструменты, карточка агента, версии. Главный сценарий покрывает создание через YAML по пустому списку.
- [Сессии и ход агента](./sessions-and-agent-run.md): новая сессия, сообщение, bash в VM, ответ, страница сессии как в консоли Claude (токены в шапке, инспектор и его вкладки «События», «Инструменты», «Ресурсы», выбор события, мини-карта, поиск, 390 px), архив. Покрыто главным сценарием.
- [Ресурсы сессии](./session-resources.md) — файл, репозиторий GitHub и хранилище памяти в окне «Новая сессия». Скрипта пока нет.
- [Навыки](./skills.md) — загрузка своего навыка, подключение к агенту, файлы навыка в песочнице. Скрипта пока нет.
- [Хранилища секретов и MCP](./vaults-and-mcp.md) — хранилище, учётные данные MCP (Bearer), MCP-сервер агента, хранилище в сессии. Скрипта пока нет.
- [Агент на Claude Code в песочнице](./claude-code-sandbox.md): окружение с `claude-agent-acp`, ключ в хранилище («переменная окружения»), агент `acp-sandbox`/`claude-acp`, ход Claude Code в VM и второй ход той же сессии (в VM один `claude-agent-acp`). Отдельный сценарий: `scripts/journey.sh --run <RUN_ID> --scenario claude-code` (экземпляр с `VERIFY_LITEBOX_DISK_SIZE_GB=4`); главный сценарий его подфункции не считает.

Отдельных файлов нет у разделов «Хранилища памяти» (`/memory`) и «Карточки моделей» (`/model-cards`); рецепт карточки моделей есть в `agents.md` (подфункция `agent-model-card`), хранилище памяти как ресурс сессии описано в `session-resources.md`.

Главный сценарий целиком: `scripts/journey.sh --run <RUN_ID>` (файл `scripts/journey-env-to-agent.mjs`).
Сценарий сам читает раздел `Sub-features` каждого файла и пишет в `summary.md` строку «не проверено» для каждой подфункции, которую не прошёл (`feature.<id>`). Новая подфункция в карте поэтому сразу видна в итоге как непроверенная.
