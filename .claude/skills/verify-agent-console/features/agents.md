# Агенты

Агент это версионируемая конфигурация: название, модель с усилием, системный промпт, инструменты, навыки, MCP-серверы и вызываемые агенты.
Пользователь создаёт агента из шаблона в форме или в режиме YAML/JSON, видит его карточку со свойствами и историей версий, правит и архивирует.
Окружения у агента нет: окружение выбирается при создании сессии.

## Sub-features

- `agent-template`: первый шаг окна «Новый агент», поиск «Поиск шаблонов» и карточки шаблонов («Пустой агент», «Глубокий исследователь» и другие).
- `agent-form`: вкладки «Основное», «Инструменты», «Навыки», «MCP-серверы», «Мультиагентность».
- `agent-model`: поле «Модель» раздела «Основное». Модели по ключу сервера и карточки рабочего пространства идут из `GET /v1/oma/model_options`, агент создаётся из формы без YAML.
- `agent-effort`: поле «Усилие» рядом с моделью. Уровни берутся из модели, значение сохраняется в `model.effort` и доходит до модели (`output_config.effort` в журнале фейка).
- `agent-code`: режимы «YAML» и «JSON» в группе «Режим правки». Форма сериализуется в YAML и обратно без потери модели и усилия.
- `agent-model-card`: карточка на странице «Карточки моделей» и её выбор в поле «Модель». Сценарии `builder` и `crud` создают карточку по API, путь через консоль сейчас не проходит ни один сценарий.
- `agent-tools`: «Включить инструменты», «Разрешение по умолчанию», режим для каждого инструмента (bash, edit, read, write, glob, grep, web_fetch, web_search). Пункта browser нет (`docs/plans/cleanup.md`, 3.3).
- `agent-detail`: `/agents/:id`, h1, регион «Свойства агента» (ID, Модель с усилием и источником, Версия, Инструменты), «Системный промпт», «История версий».
- `agent-edit`: «Изменить», затем сохранение. Версия растёт.
- `agent-archive`: «В архив».

## How to get to it (user POV)

- Боковое меню, ссылка «Агенты» (`g` `a`), маршрут `/agents`. Кнопка «Новый агент» в панели или в пустом состоянии.
- Клик по строке списка открывает `/agents/:id`. После «Создать агента» консоль сама переходит на карточку.
- Ссылка «Добавить карточку модели» внизу списка «Модель» и в предупреждении «Модели не настроены…» ведёт на `/model-cards`.

## Driving it with Playwright (verify-agent-console)

Preconditions:

- Учётка вошла в консоль. Режим модели `fake` или `real` (см. `features/README.md`).
- Карточек моделей нет. У сервера есть `ANTHROPIC_API_KEY` (в режиме fake это `verify-local-fake-key`), поэтому `GET /v1/oma/model_options` отдаёт модели каталога Pi с источником `builtin` («Ключ сервера»), и форма задаёт модель без карточек.

- **Открыть окно.** Нажать ссылку «Агенты» и дождаться h1 «Агенты» в `main` и пустого состояния «Агентов пока нет» (`agent.list_empty`; технический агент пробы к этому моменту в архиве), затем `getByRole("button", { name: "Новый агент" }).first()`. Результат: `getByRole("dialog", { name: "Новый агент" })` с подзаголовком «Выберите шаблон или соберите агента с нуля.».
- **Выбрать шаблон.** Нажать `dialog.getByRole("button", { name: /^Пустой агент/ })`. Результат: форма с полем `#agent-name`, в нём «Пустой агент». В `#agent-system` стоит промпт шаблона.
- **Модель и усилие в форме.** Заполнить `#agent-name` значением `verify-agent-<nonce>` и `#agent-system`. В разделе «Основное» нажать `combobox "Модель"` и пункт `[data-slot="command-item"][data-value^="claude-sonnet-4-6 "]` (cmdk пишет в `data-value` строку «<handle> <название>», группа «Ключ сервера»), затем `combobox "Усилие"` и `option "Низкое"`. Результат: поля `combobox "Harness"` в форме нет (с 2026-10-17 ход ведёт только Pi), «Модель» показывает название и handle, «Усилие» «Низкое», предупреждения «Модели не настроены» нет (`agent.form_model_effort`, ответ каталога в `api/29-model-options.json`). Усилие «Низкое» выбрано нарочно: pi-ai сам ставит `high`, а «По умолчанию» не задаёт поле.
- **Инструменты.** Открыть `dialog.getByRole("tab", { name: /^Инструменты/ })`. Результат: включён флажок «Включить инструменты», разрешение по умолчанию «Всегда разрешать» (`INITIAL_FORM` в `pages/agents/agentFormCodec.ts`).
- **YAML туда и обратно.** В группе «Режим правки» нажать «YAML», прочитать `textbox "Конфигурация агента в формате YAML"` (копия в `api/30-agent-create.yaml`), вернуться кнопкой «Форма» и открыть вкладку «Основное». Результат: в блоке `model:` строки `id: claude-sonnet-4-6` и `effort: low`, после возврата модель и усилие на месте (`agent.yaml_roundtrip`).
- **Создать.** Нажать `getByRole("button", { name: "Создать агента", exact: true })` в режиме «Форма». Результат: URL `/agents/<id>`, h1 с названием, `getByRole("region", { name: "Свойства агента" })` содержит `claude-sonnet-4-6` и «Усилие: низкое» (`agent.detail_ui`). Ошибка показывается блоком `[role=alert]` внутри окна.
- **Сверить запись.** Вызвать `GET /v1/agents/:id`. Результат: `name`, `model: {id: "claude-sonnet-4-6", effort: {type: "low"}}` (API отдаёт усилие объектом, на входе принимает и строку `low`), `system`, `_oma.harness` и `_oma.acp` нет, в `tools` есть `agent_toolset_20260401`, bash не отключён. Ключа `environment` нет (`agent.created`).
- **Усилие доходит до модели (`agent-effort`).** После хода главной сессии в `fake-model-requests.jsonl` у каждого запроса с nonce хода `thinking: "adaptive"` и `effort: "low"`; у запросов технического агента пробы (агент без усилия) `effort: null` (`run.fake_model_effort`). Путь: `model.effort` → `thinkingLevel` в `buildHarnessContext` (`apps/main-node/src/modules/node-managed.ts`) → pi-ai `anthropic-messages` → `thinking {type: "adaptive"}` и `output_config.effort` (у `claude-sonnet-4-6` в каталоге Pi `forceAdaptiveThinking`).
- **Модель через карточку (`agent-model-card`).** Сценария для этого пути нет, до 2026-10-17 его проходил удалённый сценарий `claude-code`. Шаги: «Карточки моделей» → «Новая карточка модели», плитка провайдера в группе «Провайдер Pi *» первой (она сбрасывает модель и адрес), `#modelcard-id`, `#modelcard-api-key`, `#modelcard-wire-model`, `#modelcard-base-url` без `/v1` для Anthropic, «Создать», тост «Карточка модели создана, ключ anthropic проверен.». Карточка появляется в группе «Карточки моделей» поля «Модель».
- **Правка.** На карточке нажать «Изменить», поменять системный промпт, сохранить. Результат: «Версия» `v2`, в «Истории версий» две записи, у текущей бейдж «Текущая».
- **Доказательство.** `screens/*agent-*.png`, `aria/*agent-detail.yml`, `api/29-model-options.json`, `api/30-agent-create.yaml`, `api/31-agent.json`, строки `agent.*` и `run.fake_model_effort` в `summary.md`.

## Gotchas

- С 2026-10-16 список «Модель» форма берёт из `GET /v1/oma/model_options`, а не из карточек. Без карточек и без `ANTHROPIC_API_KEY` у сервера список пуст, и форма пишет «Модели не настроены. Добавьте карточку модели или задайте на сервере ANTHROPIC_API_KEY». До этого без карточек группы «Модель» не было, и главный сценарий задавал модель в YAML (строка «внимание» `agent.form_without_model_cards`, её больше нет).
- Guard на `POST /v1/agents` и `POST /v1/agents/:id` (`apps/main-node/src/lib/agent-config-guard.ts`) сверяет модель с `model_options`: неизвестный handle и уровень усилия не из `effort_levels` дают 400. Агент с `harness`, отличным от `default` и `pi`, или с блоком `acp` получает отказ «Остался только встроенный цикл. Уберите harness и блок acp.». `/v1/oma/agents` (legacy) по-прежнему требует активную карточку, если хоть одна карточка есть (`modules/node-http.ts`).
- Пункты списка «Модель» это `cmdk`-пункты (`role=option`), их имя склеено из названия, handle и серой строки без пробелов. Ищите пункт по `data-value^="<handle> "`, а не по имени.
- Если карточка с `model_id`, равным `agent.model`, есть и у неё есть ключ, сервер берёт ключ и URL из карточки, а не из `ANTHROPIC_*`. Лишняя карточка может увести фейковый прогон на настоящий API.
- Усилие в ответе `GET /v1/agents/:id` лежит объектом: `model.effort = {type: "low"}` (`toAgentResponse` в `packages/managed-agents-api/src/mappers/agents.ts`), а в YAML формы строкой `effort: low`. Прогон `20261016-080856` дал провал `agent.created`, потому что сценарий ждал строку; правка в сценарии.
- Поле «Модель» ищите с `exact: true`: в разделе «Основное» есть ещё «Вспомогательная модель» (`#agent-aux-model`), и `getByRole("combobox", { name: "Модель" })` без `exact` находит оба поля. Прогон `20261016-074035` прерван на этом шаге (strict mode violation).
- При переключении «Форма» → «YAML» форма сериализуется. Обратное переключение разбирает YAML, и ошибка разбора остаётся в `[role=alert]`.
- Имя кнопки шаблона включает описание и теги. Ищите регуляркой `^Пустой агент`, а не точным именем.
- У строк таблицы агентов нет `title`, и у `section` нет подписи. Ищите строку по тексту имени.
- Список агентов в окне «Новая сессия» включает архивных агентов (`include_archived: true`). Выбирайте агента по id.
- Список «Агенты» по умолчанию показывает только активных (фильтр «Статус: Активные», `include_archived` не передаётся, `pages/AgentsList.tsx:57-60`). Поэтому технический агент пробы окружения после архива не мешает пройти путь по пустому списку.
- Подфункции `agent-model-card`, `agent-edit`, `agent-archive` главный сценарий не проходит; в `summary.md` они идут строками «не проверено» `feature.*`.
