# Ассистент платформы

Ассистент это агент пространства с меткой `oma_role: builder` и одним MCP-сервером `platform`. Пользователь открывает его панель по Ctrl I или кнопкой «Ассистент» в шапке. Без подтверждения ассистент читает, ищет и собирает черновик. Любую запись (агент, окружение, навык, деплоймент на паузе, сессия, первое сообщение в созданную им сессию, правка карточки harness) пользователь подтверждает кнопкой на карточке в панели. Сервер считает разницу, класс и отпечаток сам и отклоняет то, что изменилось после preview. Секреты к модели не попадают.
Проект: `docs/plans/builder-agent.md`, проверка по разделу 6. Подфункции этого файла считает сценарий `builder` (`scripts/journey-builder.mjs` и `scripts/journey-builder-guard.mjs`), главный сценарий их не считает.

## Sub-features

- `builder-install`: первый Ctrl I в пространстве без ассистента: «Ассистента здесь ещё нет», выбор карточки модели, «Установить» создаёт окружение «Ассистент» и агента с `always_ask` по умолчанию.
- `builder-panel`: панель справа с чипом контекста страницы («Агенты»), поле «Сообщение ассистенту», «Новый разговор», «История».
- `builder-batch`: пачка `apply_changes` «Создать 3 объекта»: ход закрыт `requires_action`, до клика объектов нет, после «Создать» окружение, навык и агент с метками `oma_created_via` и `oma_assistant_session`, строки «Создан …» со ссылками.
- `builder-deployment`: карточка «Создать деплоймент на паузе» с тремя ближайшими запусками; деплоймент `paused`, `updated_at = created_at`, за 2 минуты нет запусков и сессий.
- `builder-update`: карточка правки агента «версия 1 станет 2» с разницей, «Применить» даёт версию 2.
- `builder-session`: карточка «Создать сессию» (агент и версия, окружение, файл, строка про пустую сессию); сессия `idle` без `user.*`, с файлом и метками.
- `builder-message`: карточка «Отправить первое сообщение» с полным текстом; после «Отправить» в сессии одно `user.message`, агент сессии ответил.
- `builder-harness-draft`: черновик карточки harness, «Открыть форму» открывает «Новый harness» без ID и команды; правка карточки (`allowed_env`) со строкой про root.
- `builder-changes`: вкладка «Изменения» с журналом действий (11 строк 6.2); на 390 px панель нижним листом.
- `builder-deny`: «Отклонить» с причиной: версия прежняя, результат `is_error`, строка `denied`; прямой `user.tool_confirmation` allow даёт 403 «Подтверждайте через карточку».
- `builder-bypass`: `always_allow` у всех инструментов сессии: сервер отвечает «Нужно подтверждение», строка `refused_confirmation`.
- `builder-tool-check`: `bash` и `read` или ресурс `memory_store` в сессии ассистента: у модели нет `mcp__platform__*`, `session.warning` «MCP setup failed».
- `builder-switch`: выключатель в меню панели: «Ассистент выключен», поле выключено, инструменты отвечают `refused_disabled`, preview `disabled`, confirm 409 `disabled`; после включения карточка снова работает.
- `builder-foreign`: агент чужого пространства: `get` «не найден», карточка «Объект не найден», confirm 404.
- `builder-member`: второй участник пространства: записи в сессию ассистента, confirm и выключатель дают 403, preview отвечает, карточка без кнопок с подписью «Подтвердить может только …»; свою сессию он начинает; прямой вход в `/v1/oma/platform-mcp` с cookie и ключом API 403.
- `builder-inject`: указания внутри файла и `SKILL.md` при `always_allow`: четыре `refused_confirmation` и ни одного побочного действия; при обычной политике карточка с `VB_EVIL` и «Отклонить».
- `builder-stale`: агента поменяли после preview: 409 `stale`, «Агент изменился после предложения», «Применить» выключена, «Попросить пересобрать».
- `builder-class`: деплоймент сняли с паузы после preview: 409 `class` с причиной на карточке.
- `builder-mempath`: путь памяти заняли после preview: 409 `stale`, карточка «Создать запись памяти» стала «Изменить запись памяти», «Применить» пишет текст модели.
- `builder-msg`: в сессию уже написали или сессию создал не этот разговор: 409 `class`, причина про первое сообщение.
- `builder-secrets`: канарейки (ключи карточек, заголовок, логин и пароль адресов, учётные данные, короткие значения, base64 и URL-кодировка, копии скрытых полей, `ghp_` и `sk-`, ротация) не доходят до модели; подбор секрета по префиксам ничего не находит.
- `builder-qwen`: живая проверка на Qwen по команде владельца (6.8): помощник обычными словами готовит агента, окружение, сессию и первое сообщение.

## How to get to it (user POV)

- Кнопка «Ассистент» в шапке любой страницы или Ctrl I. Первый раз панель предлагает установить ассистента и выбрать карточку модели.
- Меню «…» в шапке панели («Меню ассистента») у владельца и администратора: «Выключить ассистента в пространстве» и «Включить ассистента».
- Карточки предложений в ленте панели: «Создать», «Применить», «Отправить», «Отклонить», «Обновить», «Попросить пересобрать», ссылка «Отклонить с причиной».
- Страница `/sessions/:id` показывает ждущие вызовы блоком «Ожидает подтверждения»: для вызовов платформы там только «Отклонить».

## Driving it with Playwright (verify-agent-console)

Preconditions:

- Экземпляр в режиме fake (`scripts/launch.sh`), `doctor.sh`, затем `seed-user.sh --run "$RUN" --others`: участник пространства с ролью `member` и второй пользователь со своим пространством. Без `--others` шаги 6.4 падают.
- `launch.sh` запускает фейк с `--canary-file state/canaries.json --oracle-file state/oracle.json`. Файлы пишет сценарий до первого хода ассистента.
- Сценарий: `scripts/journey.sh --run "$RUN" --scenario builder`. Отдельные шаги: `VERIFY_BUILDER_ONLY=6.2,6.7` (подстроки имён шагов, вход и подготовка идут всегда).

- **Установка.** Ссылка «Агенты», `Control+i`, `aside[aria-label="Ассистент"]`, текст «Ассистента здесь ещё нет», первый `select` панели → `vb-fake-<n>`, «Установить». Результат: поле `textbox "Сообщение ассистенту"` включено, `GET /v1/agents` даёт агента с `metadata.oma_role: builder` (`vb.install`).
- **Маркер.** Реплика в поле панели и Enter. Маркер `VERIFY_BUILDER[_<ВИД>] nonce=<n>`, ниже строки `Ключ: значение` с id (`Модель`, `Файл`, `Цель`, `Версия`, `Окружение`, `Сессия`, `Навык`, `Хранилище`). Решения фейка в `scripts/fake-model-builder.mjs`, шаг равен числу результатов инструментов после маркера.
- **Карточки.** `article.assistant-card[data-tool="<инструмент>"][data-phase="pending"]` в панели. Ждать, пока пропадёт «Готовлю предложение». Кнопки по имени: «Создать», «Применить», «Отправить», «Отклонить» (отказ уходит сразу, без причины). Отказ с причиной: ссылка «Отклонить с причиной» → поле «Причина отказа» → «Отправить отказ». Состояние хода сверять по журналу: следующий `session.status_idle` и его `stop_reason`.
- **Разговор.** id разговора лежит в `localStorage` под ключом `oma_assistant_chat:<пространство|default>`. Сессии ассистента без панели создаются по API с меткой `oma_assistant_chat: "1"` и `oma_assistant_user`, тогда их видно в «Истории».
- **Отпечатки.** Сценарий слушает ответы `POST /v1/oma/platform-mcp/preview` и `/confirm` страницы и сверяет `preview_digest` строк `GET /v1/oma/platform-mcp/actions` (`confirmations`) с тем, что консоль получила от preview (`vb.confirmations`).
- **Секреты.** `stepSeedSecrets` кладёт контрольные значения через API (карточки моделей, хранилище секретов, память, файлы, навык, агенты, деплоймент в архиве, сессия с мёртвой карточкой) и пишет `canaries.json`. Итог: `vb.canary_hits` (нет строк `canary_hit`) и `vb.canary_not_logged`.

## Gotchas

- Сессию с секретами в сообщении пользователя ведёт агент на мёртвой карточке `vb-dead-<n>` (`http://127.0.0.1:9`). Иначе ход этой сессии отправил бы секреты фейку, и `canary_hit` поймал бы не ассистента.
- Повторяющееся поле `files[]` навыка Playwright в `multipart` не передаёт, навыки сценарий грузит через `fetch` с `FormData` и cookie браузера.
- Журнал фейка в доказательствах копируется с заменой значений канареек на `[канарейка]`; сырой журнал остаётся в папке прогона и удаляется cleanup.
