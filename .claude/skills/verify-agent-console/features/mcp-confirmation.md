# Подтверждение вызовов MCP

Инструмент MCP-сервера без явной политики не меняет данные во внешней системе сам. Ход агента встаёт на `requires_action`, над полем ввода страницы сессии появляется блок «Ожидает подтверждения» с кнопками «Разрешить» и «Отклонить». Одно «Разрешить» исполняет вызов ровно один раз, повторное «Разрешить» не исполняет его снова и не будит модель. «Отклонить» не пускает вызов на сервер, а модель получает отказ с причиной. Сохранённые агенты с явным `always_allow` не меняются, карточка помечает такой сервер «без подтверждения».
Проект: `docs/plans/cma-wave-1.md`, функция 3.1. Подфункции этого файла считает сценарий `mcp-ask` (`scripts/journey-mcp-ask.mjs`), главный сценарий их не считает.

## Sub-features

- `mcp-ask-waits`: агент из формы консоли со своим MCP-сервером, сессия с хранилищем; вызов `write_act` останавливает ход (`requires_action`, `evaluated_permission: ask`), блок «Ожидает подтверждения», в журнале fake-mcp вызова нет.
- `mcp-ask-allow`: «Разрешить» исполняет `write_act` один раз и после клика, результат доходит до модели, ход кончается ответом, блок уходит.
- `mcp-ask-repeat`: второе «Разрешить» на исполненный `write_act` (по API, кнопки уже нет): вызов не уходит снова, модель не просыпается, во «Инструментах» у `write_act` 1 вызов.
- `mcp-ask-deny`: «Отклонить» с причиной: `write_act` не уходит во внешнюю систему, `agent.mcp_tool_result` с `is_error` и причиной, модель отвечает после отказа.
- `mcp-ask-exception`: в форме агента у сервера поле «Разрешение», у «Всегда разрешать» предупреждение, исключение `read_report` «Всегда разрешать» уходит в `configs` набора; в новой сессии `read_report` идёт без карточки подтверждения.
- `mcp-ask-old-agent`: агент с набором MCP на явном `always_allow`, как его сохраняла консоль до функции 3.1: карточка пишет «MCP: <сервер>, без подтверждения», форма показывает «Всегда разрешать» с предупреждением, правка имени набор не меняет.

## How to get to it (user POV)

- Форма агента, вкладка «MCP-серверы», «Свой сервер»: название, тип URL, адрес, поле «Разрешение» («Всегда спрашивать» у нового сервера) и блок «Исключения по инструментам» с кнопкой «Добавить исключение».
- Страница агента, свойство «Инструменты»: сервер на «Всегда разрешать» подписан «MCP: <имя>, без подтверждения».
- Окно «Новая сессия»: флажок хранилища с токеном для адреса сервера.
- Страница сессии: блок «Ожидает подтверждения» над полем «Сообщение», в строке вызова «сервер / mcp__сервер__инструмент», вход JSON, поле «Причина отказа», кнопки «Разрешить» и «Отклонить» (`components/session/ToolConfirmationRequests.tsx`). Строка вызова в ходе должна быть подписана «Ждёт вас» (`ToolStatus` в `components/session/CanonicalSessionTurn.tsx`).
- Повторное «Разрешить»: в консоли кнопки после первого клика нет. Повтор приходит от клиента SDK, второй вкладки или двойного запроса: `POST /v1/sessions/:id/events` с `user.tool_confirmation` на тот же `tool_use_id`.

## Gotchas

- Если `mcp.write_waits` провален, `write_act` уже ушёл без человека. Шаги «Разрешить» и «Отклонить» тогда пишутся строками «не проверено», а второй ход не отправляется: иначе во внешнюю систему ушёл бы ещё один вызов без человека. Так выглядит прогон до среза 2 функции 3.1: консоль пишет новому серверу `always_allow`, сервер подставляет `always_allow` в набор без политики, и в журнале fake-mcp ровно один `write_act`.
- Без учётных данных в хранилище сессии прокси main-node отвечает 403 (`resolveNodeMcpProxyTarget` в `apps/main-node/src/modules/node-managed.ts`), инструменты сервера в ход не попадают, а в журнале сессии `session.warning` «MCP setup failed». Адрес в учётных данных должен совпадать с адресом сервера агента до символа.
- fake-mcp отвечает -32601 на `server/discover`, клиент MCP v2 после этого идёт через `initialize`. В журнале на каждое подключение строки `server/discover`, `initialize`, `notifications/initialized`, GET с 405 и `tools/list`.
- Окружение с сетью «Ограниченный» без «Разрешить сетевой доступ MCP-серверам» выключает MCP-серверы целиком (`mcpDisabledByEnvironment` в `apps/agent/src/harness/tools.ts`), поэтому сценарий заводит своё окружение «Без ограничений».
- Решения фейка: маркер `VERIFY_TOOL nonce=<n>` со строками `Инструмент:` и `Вход:` (`scripts/fake-model.mjs`, `decideTool`).
- До правки консоли 2026-10-18 строка ожидающего вызова в ходе была подписана «Прервано», а не «Ждёт вас», и `mcp.ui_waiting_row` писал «внимание». Причин было две. `collectToolCalls` (`apps/console/src/lib/session-stats.ts`) закрывал вызов на любом `session.status_idle`, даже когда `stop_reason` равен `requires_action`. После перезагрузки `@openma/common` режет ходы по `status_idle`, и подтверждение с результатом уходили в следующий ход; теперь `ManagedSessionConversation` передаёт `buildTranscriptBlocks` вызовы всей сессии (опция `toolCalls`). Обе проверки строки теперь пишут провал. Блок «Ожидает подтверждения» над полем ввода проверяет `mcp.write_waits`.
- До правки раннера 2026-10-18 (находка 1 ревью) второе `allow` не исполняло вызов, но будило модель на законченной истории: в журнале сессии появлялся второй `agent.message`, у фейковой модели новый запрос. `mcp.repeat_allow_none` ловит это по `agent.message`, `span.model_request_start` и журналу фейка, а не только по журналу fake-mcp.
