# Ресурсы сессии

Раздел «Ресурсы (необязательно)» в окне «Новая сессия» подключает к сессии то, что попадает в песочницу агента до его первого хода:
репозиторий GitHub (клонируется в `/workspace/<имя>`), файл из раздела «Файлы» (кладётся в `/mnt/session/uploads/<file_id>` или свой путь) и хранилище памяти (монтируется в `/mnt/memory/<имя>`).
Ресурсы задаются только при создании сессии, менять их в открытой сессии консоль не даёт.

## Sub-features

- `session-resource-file` — кнопка «Файл»: выбор файла `Выберите файл…` и «Путь монтирования (необязательно)».
- `session-resource-github` — кнопка «Репозиторий GitHub»: URL, токен (обязателен), ветка или коммит, путь монтирования.
- `session-resource-memory` — кнопка «Хранилище памяти»: выбор хранилища и «Доступ» («Чтение и запись» или «Только чтение»).

## How to get to it (user POV)

- «Сессии» → «Новая сессия» → раздел «Ресурсы» под полем названия. Пока ресурсов нет, видно «Ресурсы не добавлены.».
- Кнопки «Репозиторий GitHub», «Файл», «Хранилище памяти» добавляют строку ресурса, кнопка «Убрать» в строке её удаляет.
- Файл заранее загружается в разделе «Файлы» (`/files`) или запросом `POST /v1/files`; ссылка «Управление файлами» ведёт туда.
- Хранилище памяти заранее создаётся в разделе «Хранилища памяти» (`/memory`); ссылка «Управление хранилищами».

## Driving it with Playwright (verify-agent-console)

Preconditions:

- Учётка вошла в консоль, агент `verify-agent-<n>` и окружение `verify-env-<n>` созданы (см. `agents.md`, `environments.md`).
- Скрипта для ресурсов пока нет; главный сценарий их не задаёт, поэтому в `summary.md` подфункции этого файла идут строками «не проверено».
- Для файла: файл с маркером `VERIFY_FILE_<n>` загружен через «Файлы» (или `POST /v1/files` с beta `files-api-2025-04-14`).

- **Файл.** В окне «Новая сессия» нажать кнопку «Файл», открыть `getByRole("combobox", { name: "Выберите файл…" })` и выбрать `getByRole("option", { name: /<имя файла>/ })`. Создать сессию. Результат: `GET /v1/sessions/:id` содержит `resources` с `type: "file"` и `file_id`. Промпт (режим fake): `Команда: cat /mnt/session/uploads/<file_id> && echo VERIFY_OK_<n>`, строка `VERIFY_AGENT_RUN nonce=<n>`. Ожидается `agent.tool_result` с `VERIFY_FILE_<n>` и `VERIFY_OK_<n>`.
- **Хранилище памяти.** Создать хранилище в «Хранилища памяти», в окне «Новая сессия» нажать «Хранилище памяти», выбрать его в `combobox` «Выберите хранилище…», доступ «Только чтение». Результат: `resources` с `type: "memory_store"`; в VM есть `/mnt/memory/<имя>` и переменная `OMA_MEMORY_DIR=/mnt/memory` (`apps/main-node/src/lib/node-managed-session-inputs.ts:235-271`).
- **Репозиторий GitHub.** Нужен доступный репозиторий и токен; на этом стенде без сети к GitHub и без токена путь «не проверено». Ожидается клон в `/workspace/<имя репозитория>` (путь по умолчанию строит `defaultMountPath` в `pages/SessionsList.tsx`).
- **Доказательство.** Скриншот окна с заполненным ресурсом, `api/session-with-resources.json`, журнал событий сессии с выводом `cat`/`ls`.

## Gotchas

- Ресурсы попадают в VM при подготовке песочницы, то есть при первом инструменте агента, а не при создании сессии (`node-managed-session-inputs.ts`). Ошибка ресурса (файл не найден, нет токена GitHub) видна только в первом ходе как `session.error`, а не при создании.
- Строка ресурса без выбранного файла или хранилища молча отбрасывается при создании (`pages/SessionsList.tsx:425-462`: `if (!r.file_id) continue`). Проверяйте `resources` в `GET /v1/sessions/:id`, а не только видимую строку в окне.
- Для репозитория токен обязателен: без него строка пропускается (`SessionsList.tsx:431`), а сервер требует сохранённый токен (`node-managed-session-inputs.ts:298-302`).
- Хранилище с доступом «Чтение и запись» требует поколения рантайма (`runtimeGeneration`), иначе ход падает с «Writable Managed Memory Store … requires a runtime generation» (`node-managed-session-inputs.ts:245-252`). Для первой проверки берите «Только чтение».
- Если в списке файлов пусто, в окне видна подсказка «Файлов пока нет. Загрузите файл через SDK или запрос POST /v1/files.».
