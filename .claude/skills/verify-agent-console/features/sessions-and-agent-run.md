# Сессии и ход агента

Сессия связывает агента с окружением. Пользователь создаёт сессию, пишет сообщение, и агент работает:
вызывает модель, выполняет инструменты в песочнице LiteBox (микро-VM) и отвечает.
Ход виден в разговоре и на вкладке «Хронология». Файлы, которые агент сохранил в `/mnt/session/outputs`, видны в панели «Файлы сессии».

## Sub-features

- `session-create` — окно «Новая сессия»: агент, окружение, название, хранилища. Ресурсы окна описаны отдельно в `session-resources.md`.
- `session-turn` — сообщение, ход агента с `bash` в VM, итоговый ответ.
- `session-answer`: ответ хода в разговоре: итоговый ответ и первое сообщение хода видны целиком и без повторов, подпись «Работал N с» показывает реальную длительность, а не «0 с».
- `session-tool-card` — карточка инструмента в разговоре: команда и вывод.
- `session-timeline` — вкладка «Хронология» со строками инструментов и вызовов модели.
- `session-files` — панель «Файлы сессии» (`GET /v1/sessions/:id/outputs`).
- `session-archive` — архив сессии. Песочница уничтожается, VM останавливается.

## How to get to it (user POV)

- Боковое меню, ссылка «Сессии» (`g` `s`), маршрут `/sessions`, кнопка «Новая сессия». После «Создать» консоль переходит на `/sessions/:id`.
- Клик по строке списка сессий открывает `/sessions/:id`.
- На странице сессии: поле «Сообщение» и кнопка отправки (Enter отправляет, Shift+Enter переносит строку); вкладки «Разговор» и «Хронология»; кнопка «Файлы сессии». Подпись кнопки зависит от статуса: «Отправить сообщение» при idle, «Поставить сообщение в очередь» при running (`ComposerPrimaryAction` в `components/session/SessionComposer.tsx`).

## Driving it with Playwright (verify-agent-console)

Preconditions:

- Агент `verify-agent-<nonce>` и окружение `verify-env-<nonce>` созданы (см. `agents.md`, `environments.md`).
- Режим fake: фейковая модель отвечает на `127.0.0.1:8792` (`scripts/doctor.sh`). Промпт содержит строки `Команда: <cmd>` и `VERIFY_AGENT_RUN nonce=<n>`.
- Весь путь выполняет `scripts/journey.sh`, шаги «сессия» и «ход агента».

- **Новая сессия.** Нажать ссылку «Сессии», затем `getByRole("button", { name: "Новая сессия" }).first()`. Результат: `getByRole("dialog", { name: "Новая сессия" })`. Агент и окружение подставлены по умолчанию первыми в списке.
- **Выбрать агента и окружение.** Нажать `dialog.getByRole("combobox").nth(0)`, выбрать `[data-slot="command-item"]` с id агента. Затем то же для `nth(1)` с id окружения. Результат: в тексте каждого combobox видно `<имя> (<id>)`.
- **Название и создание.** Заполнить `#session-title` значением `verify-session-<nonce>` и нажать `getByRole("button", { name: "Создать", exact: true })`. Ожидаемый результат: URL `/sessions/<id>`, h1 с названием, бейджи `[title="Агент: …"]` и `[title="Окружение: …"]`. `GET /v1/sessions/:id` возвращает `agent.id`, `environment_id`, `title` и `status = idle`. До первого сообщения в шапке «Ожидает», а в пустом разговоре нет «Агент работает…» (проверка `session.initial_status`: API, плашка статуса и текст страницы). Прогон 2026-10-16 (`20261016-002808`): `title` сохранён, h1 с названием (`session.title_saved` проверено; до правки консоли 2026-10-15 было `title = null`). Папки `<прогон>/data/sandboxes/<id>` ещё нет: песочница ленивая.
- **Сообщение.** До отправки открыть параллельно с консолью поток `GET /v1/sessions/:id/events/stream` (cookie браузера, `captureStream` в сценарии). Заполнить `getByRole("textbox", { name: "Сообщение" })` и нажать `getByRole("button", { name: /^(Отправить сообщение|Поставить сообщение в очередь)$/ })`. В новой сессии подпись «Отправить сообщение» (это проверка `run.ui_send_label`; регулярное выражение терпит вторую подпись, чтобы при провале ход всё равно запустился). Перед снимком дождаться, что поле ввода очистилось.
  Ожидаемый результат: в `article[data-turn-id]` реплика `[data-session-turn-prompt]` с `nonce=<n>`.
  Прогон 2026-10-16: реплика стоит в ходе сразу после отправки (`run.ui_prompt_on_send`, `screens/*-turn-prompt-visible.png`), после конца хода (`run.ui_prompt_visible`) и после перезагрузки (`run.ui_prompt_after_reload`); поток отдаёт `user.message` с маркером (`run.sse_user_message`). Как это устроено, см. в Gotchas.
- **Конец хода.** Опрашивать `GET /v1/sessions/:id/events?order=asc&limit=100` (с `page=next_page`), пока после `user.message` не появится `session.status_idle`. Результат:
  - события идут в порядке `agent.message{первое сообщение}` → `agent.tool_use{name:"bash"}` → `agent.tool_result{tool_use_id, content содержит VERIFY_OK_<n>}` → `agent.message{итоговый ответ с VERIFY_DONE_<n>}` → `session.status_idle{stop_reason.type:"end_turn"}`. Первое сообщение фейковая модель шлёт только в ходе агента (`VERIFY_AGENT_RUN`), в пробах окружения его нет;
  - `GET /v1/sessions/:id` возвращает `status = idle`;
  - в интерфейсе `article` получил `data-session-turn-status="completed"`, а `[data-session-turn-answer]` содержит `VERIFY_DONE_<n>`.
- **Ответ целиком и длительность.** В режиме fake модель в ходе 1 пишет текст перед `tool_use` (`leadText`, больше 100 символов), а итоговый ответ (`finalRunText`) состоит из строки, блока кода с `VERIFY_DONE_<n>` и строки после него. Оба текста лежат в `api/fake-model-requests.jsonl` (`reply_text` у решений `tool_use` и `final_text`).
  Ожидаемый результат:
  - `run.answer_full`: журнал хранит оба текста модели как два `agent.message`. В `[data-session-turn-answer]` есть каждая строка итогового ответа по порядку (кроме строк-ограждений блока кода; текст ответа в `api/46-turn-answer-text.txt`). После клика по `[data-chat-reasoning-trigger]` первое сообщение видно целиком. В fake каждый текст стоит на странице ровно один раз. Строки обоих текстов не срезаны на экране (`clippedLine`: коробка самого глубокого элемента со строкой внутри предков с `overflow: hidden` или `clip` до ближайшей прокрутки; снимок `screens/*-turn-answer-full.png`);
  - `run.turn_duration`: длительность хода по журналу (`processed_at` от `user.message` до `session.status_idle`) больше секунды, поэтому на странице нет «Работал 0 с» и «Думал 0 с». Подпись «Работал N с» не больше длительности по журналу плюс 2 с. Если консоль длительность не показывает, проверяется только отсутствие «0 с».
  Если начало ответа срезано, падают обе проверки: `run.answer_full` и `run.ui_turn_done`. Срез на длину первого сообщения (105 символов) уносит `VERIFY_DONE_<n>` целиком.
- **Карточка инструмента.** Нажать `[data-chat-reasoning-trigger]` («Работал N с»), при группе ещё кнопку «Использовано N инструментов» (одного инструмента несколько раз: «Использован 1 инструмент, N вызовов»), затем `[data-slot="collapsible-trigger"]` с текстом `bash`. Результат: `[data-slot="collapsible-content"]` содержит `VERIFY_OK_<n>` (`run.ui_tool_card`).
  Вывод должен читаться как текст: `kernel=` на своей строке, без `"type": "text"`, литералов `\n` и `\u001b` (`run.ui_tool_output_text`, текст карточки в `api/45-tool-card-text.txt`). В прогоне 2026-10-16 проверено: `VERIFY_OK_<n>` и `kernel=…` на своих строках. До правки консоли (2026-10-15) карточка показывала JSON-массив content-блоков.
- **Хронология.** Нажать `getByRole("tab", { name: "Хронология" })`. Результат: есть строка `[title^="bash · "]`, рядом «Вызов модели» и «Ответ агента».
- **Файлы сессии.** Нажать `getByRole("button", { name: "Файлы сессии" })`. Результат: в `getByRole("complementary", { name: "Файлы сессии" })` есть ссылка `verify-<n>.txt`. Те же файлы видны через `GET /v1/sessions/:id/outputs`. На хосте лежит `<прогон>/data/session-outputs/<tenant>/<session>/verify-<n>.txt` с содержимым `VERIFY_OK_<n>`, записанным внутри VM.
- **Это VM, а не хост.** Значение `kernel=` в выводе bash не равно `uname -r` хоста. По runbook ядро в VM 6.12.76, на хосте 6.18.55. Дополнительно есть `<прогон>/data/sandboxes/<id>/.openma/litebox-scratch-*`, «Box started successfully» в `BOXLITE_HOME/logs` и процесс `libkrun VM` (pid из строки `boxlite-shim subprocess spawned`) это прямой потомок server-node. В логе сервера есть строка `creating box (image=…, network=…)` от `litebox-sandbox` (`run.server_log_box`).
- **Архив.** Вызвать `POST /v1/sessions/:id/archive` (это делает сценарий и `scripts/cleanup.sh`). Результат: `archived_at` задан, в логе BoxLite новая строка «Box stopped», scratch удалён. Папка `sandboxes/<id>` остаётся: её стирает только удаление сессии.
- **Доказательство.** `screens/*session*.png`, `screens/*turn*.png`, `screens/*timeline.png`, `screens/*session-files.png`, `aria/*turn-done.yml`, `api/40…46-*`, `api/41-session-stream.json` (поток событий), `api/fake-model-requests.jsonl`, строки `run.*` в `summary.md`.

## Gotchas

- `combobox` «Агент» и «Окружение» не связаны с подписями (`pages/SessionsList.tsx:820,852`). Берите их по порядку в окне, а выбор подтверждайте по id в тексте.
- В фейковом режиме ответ модели определён заранее. В режиме real проверяйте события `tool_use` и `tool_result` и маркер `VERIFY_OK_<n>` в выводе, а не точный текст ответа. `run.answer_full` в режиме real сверяет страницу с последним `agent.message` журнала и не считает повторы. Строки сравниваются только по буквам и цифрам (`markdownLines`, `missingInOrder`): разметка Markdown не даёт ложного провала, а срезанное начало ответа видно.
- **Почему ответ резался.** `AgentUITurnView` из `@openma/common` передаёт в `renderAssistant` и `renderThought` значение `prefixSkip` из `streamPrefixes` (`node_modules/.pnpm/@openma+common@0.9.1*/node_modules/@openma/common/dist/chat-ui/components.js:537-553`). Это сумма длин всех предыдущих сообщений ассистента в ходе, то есть смещение в общей склейке текстов хода для потокового `AgentUIStreamingMarkdown`, а не длина префикса самого сообщения. В канонических событиях managed-сессии каждое `agent.message` отдельное и полное. Консоль рисовала `item.text.slice(prefixSkip)` (`renderAssistant` в `managedTurnSlots`, `components/session/CanonicalSessionTurn.tsx`), и итоговый ответ терял столько символов, сколько было в сообщениях до него. В сессии владельца `session_SnN30KeA8gBY-4j-bOcqm` (Qwen, Pi) первое сообщение было 58 символов, и от ответа остались «ld!» и пустой блок кода. До 2026-10-16 фейковая модель в ходе 1 отдавала только `tool_use`, в ходе было одно сообщение, и прогон дефект не видел. Правку библиотеки в `node_modules` не делайте. С 2026-10-16 консоль показывает `item.text` целиком и `prefixSkip` не использует: пункты хода из журнала всегда полные, у ACP тоже (`apps/agent/src/harness/acp-translate.ts` пишет одно `agent.message` на закрытое сообщение, чанки консоль держит вне `events`). Срез по совпадению начала терял бы «Готово.» в ответе «Готово. Итог: ...».
- **«Работал 0 с».** Подпись считает `agentUITurnElapsedSeconds` (`@openma/common/dist/agent-ui/presentation.js:68`) по `turn.startedAt` и `turn.endedAt`. `projectCanonicalSessionTurn` их не задавал, поэтому выходило 0. «Думал 0 с» у мыслей даёт `labels.thoughtFor?.(0)`: библиотека всегда передаёт 0. Длительность для `run.turn_duration` берётся из `processed_at` событий хода.
- **Анимация раскрытия.** Блок процесса раскрывается CSS-переходом `height` за 220 мс (`.reasoning-collapse-inner` с `overflow: hidden`, `@openma/common/dist/chat-ui/styles.css`). `innerText` отдаёт текст блока сразу, даже свёрнутого, поэтому проверка по тексту проходит, а снимок сразу после клика показывает срезанное первое сообщение (прогон `20261016-021859`: видна одна строка из двух, шеврон повёрнут наполовину). После клика сценарий ждёт конца анимаций (`settleAnimations`: `getAnimations({ subtree: true })`, затем высота хода не меняется), и `clippedLine` проверяет, что строки не срезаны. Без ожидания `run.answer_full` падает с «предок div.reasoning-collapse-inner (overflow hidden) показывает 7 из 48 px» (прогон `20261016-023057`).
- Порядок в раскрытом блоке процесса задаёт библиотека: сначала карточки инструментов (`processActivitySequences`), потом тексты ассистента (`ChatReasoningContent`, `components.js:493-505`). Поэтому «Запускаю проверочную команду…» стоит под карточкой bash, хотя в журнале идёт до `tool_use`. Сценарий порядок не проверяет.
- **Разовый сбой VM: `spawn_failed … InitReady`.** Прогон `20261016-021532`: первая же команда в новой VM главной сессии (`mkdir -p /workspace` в `initializeBox`) упала с `internal error: spawn_failed: internal error: build failed: failed to create container: received unexpected message: InitReady, expected: IntermediateReady(0)` (libcontainer в госте BoxLite). VM стартовала (`Box started successfully`), через 2 с адаптер остановил её. Две пробы того же прогона на том же окружении прошли; повтор цепочки (`20261016-021859`) прошёл без сбоя. Прогон `20261016-040821`: тот же сбой на сетевом ходе пробы окружения (`env.probe.network`); команда не стартовала, VM осталась живой, следующая команда в ней прошла. Повтор `20261016-041400` на том же дереве прошёл. Чем это видно в отчёте: `agent.tool_result` с текстом `Error: internal error: spawn_failed…` и `is_error: false`, ответ фейка `VERIFY_FAIL_<n>`, провалы `run.tool_result`, `run.in_vm`, `run.answer`, `run.answer_full`, `run.outputs_*`, `run.vm_process`, `run.vm_stopped` (VM уже остановлена, в логе сервера `destroy stop failed: … spawn_failed …` при архиве). Два слабых места продукта (на 2026-10-16 не исправлены): `ensureBox` (`packages/sandbox-adapter-litebox/src/litebox.ts`) оставляет отклонённый `boxPromise`, поэтому все следующие команды сессии получают ту же ошибку без новой попытки; а ошибка песочницы приходит в `tool_result` без `is_error`. При таком провале повторите цепочку; если сбой повторится, это уже не разовый сбой.
- После завершения хода блок процесса скрыт (`hidden`, `inert`). Без клика по `[data-chat-reasoning-trigger]` карточки инструмента не видно. С 2026-10-16 разговор показывает каждый вызов (`activityTools="all"`), повторы одного инструмента не схлопываются, подпись группы считает и инструменты, и вызовы.
- Поток `/events/stream` может не отдавать историю, поэтому для проверки используйте опрос `/events`. Если session.status_idle пришёл раньше, чем вы начали ждать, ищите его в журнале после своего `user.message`.
- **Откуда реплика в ходе.** Консоль строит ход из событий (`projectCanonicalChatTurns` в `@openma/common/session-events/managed`): ход без `user.message` не имеет `userText`, и `[data-session-turn-prompt]` не рисуется. Сейчас реплика приходит двумя путями. Консоль сразу кладёт локальное событие `user.message` (`lib/optimistic-user-message.ts`, функция `send` в `pages/SessionDetail.tsx`) и снимает его, когда из потока приходит серверный `user.message` с тем же id или текстом. main-node публикует принятые `user.*` в поток до передачи хода (`publishAccepted` в `apps/main-node/src/lib/node-managed-session-runtime.ts`). `system.user_message_pending` на main-node не шлётся. До правок 2026-10-15 не было ни того, ни другого, и реплика появлялась только после перезагрузки.
  В `api/41-session-stream.json` текст `user.message` хранится целиком: маркер `nonce=<n>` стоит в конце промпта, обрезка до 160 символов давала ложное «внимание» `run.sse_user_message` (прогон `20261016-001648`).
- **Вывод bash в карточке.** Текст готовит `formatToolOutput` (`lib/tool-output.ts`): склеивает текстовые content-блоки переносами и убирает ANSI. Вызовы: `renderTool` в `managedTurnSlots` (`components/session/CanonicalSessionTurn.tsx`) и `EventRender` в `pages/SessionDetail.tsx`. `isJsonText` в `components/ai-elements/tool.tsx` рисует JSON только для текста, который разбирается `JSON.parse`. До правки 2026-10-15 карточка показывала JSON-массив content-блоков.
- Сбой песочницы выглядит так: `session.error{retry_status: retrying | exhausted}`, затем `session.status_idle{stop_reason.type:"retries_exhausted"}`. Это провал, а не «ход закончился».
- Сетевые команды в bash до правки 2026-10-16 обрывали exec BoxLite (падение boxlite-shim на DNS, см. `environments.md`). Сейчас сеть в VM работает, но главная сессия сеть по-прежнему не использует: сетевые проверки живут в пробах окружения.
- `ANTHROPIC_BASE_URL` задаётся без `/v1`. Pi передаёт его в SDK как есть, и запрос уходит на `<base>/v1/messages?beta=true`.
- Пустая строка `ANTHROPIC_API_KEY=` считается незаданной (`apps/main-node/src/config.ts`), старт не падает. `launch.sh` всё равно задаёт ключ явно и ставит `DREAM_CURATOR_MODE=dedup`.
- Инструмент `read` для картинок и PDF ждёт префикс `exit=N`, которого LiteBox не выдаёт. Скорее всего, картинка вернётся как сырой base64. Это не проверялось.
- Если удалить окружение раньше сессии, архивировать сессию не получится, и VM не остановится (`packages/managed-agents-adapters-runtime/src/session-lifecycle-router.ts:75-84`).
- Название из окна «Новая сессия» ведёт `Controller` (`pages/SessionsList.tsx`, поле `title` окна «Новая сессия»); имя поля `oma-session-title` оставлено для автозаполнения браузера. С `{...register("title")}` и подменённым `name` ввод терялся: `onChange` react-hook-form ищет поле по `event.target.name`. Не проверяйте название переименованием через карандаш в шапке: `session.title_saved` проверяет именно окно создания.
- **Начальный статус сессии.** Сервер ставит `running` только если `initialEvents` запускают ход (`user.message` или `user.define_outcome`), иначе `idle` (`admitsBootstrapTurn` в `packages/managed-agents-application/src/sessions/application.ts`, то же правило, по которому outbox ставит bootstrap-исполнение).
