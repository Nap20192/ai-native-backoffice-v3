# Сессии и ход агента

Сессия связывает агента с окружением. Пользователь создаёт сессию, пишет сообщение, и агент работает:
вызывает модель, выполняет инструменты в песочнице LiteBox (микро-VM) и отвечает.
Страница сессии повторяет консоль Claude (`docs/plans/session-page.md`, образец `docs/cma-console/03-sessions.md`): шапка с чипами агента, окружения, длительности и последней активности; слева поиск, мини-карта и лента карточек по запросам к модели; справа инспектор с вкладками «Сессия», «События», «Инструменты», «Ресурсы», «Потоки».
Токенов, стоимости и бюджета на странице нет, потому что модели внутренние.
Файлы, которые агент сохранил в `/mnt/session/outputs`, видны на вкладке «Ресурсы».

## Sub-features

- `session-create`: окно «Новая сессия»: агент, окружение, название, хранилища. Ресурсы окна описаны отдельно в `session-resources.md`.
- `session-turn`: сообщение, ход агента с `bash` в VM, итоговый ответ.
- `session-answer`: ответ хода в разговоре: итоговый ответ и первое сообщение хода видны целиком и без повторов, подписи длительности («Работал N с», «Думал N с») не «0 с».
- `session-tool-card`: строка вызова в разговоре раскрывается кликом: блок команды, вывод текстом, длительность как в журнале.
- `session-no-usage`: шапка, подсказки её чипов, меню «Действия» и вкладка «Сессия» без токенов, стоимости и бюджета, хотя журнал хранит `model_usage`; чипы длительности и активности на месте.
- `session-inspector`: инспектор закрывается и открывается, в нём 5 вкладок, вкладка в адресе (`?inspector=`).
- `session-inspector-events`: вкладка «События»: строки `user.message` и `agent.tool_use` хода, выбор строки показывает JSON события.
- `session-inspector-tools`: вкладка «Инструменты»: вызовы и ошибки `bash` как в журнале.
- `session-select-sync`: клик по вызову в разговоре ставит `?event=<id>` и выделяет строку в «Событиях».
- `session-minimap`: мини-карта «Карта хода»: отрезки реплики и запросов к модели, карточка при наведении.
- `session-search`: поиск «Найти в разговоре»: счётчик совпадений, подсветка, метки на мини-карте.
- `session-mobile`: на 390 px у страницы нет горизонтальной прокрутки, инспектор встаёт нижним листом.
- `session-files`: выходные файлы на вкладке «Ресурсы» инспектора (`GET /v1/sessions/:id/outputs`).
- `session-archive`: архив сессии. Песочница уничтожается, VM останавливается.

## How to get to it (user POV)

- Боковое меню, ссылка «Сессии» (`g` `s`), маршрут `/sessions`, кнопка «Новая сессия». После «Создать» консоль переходит на `/sessions/:id`.
- Клик по строке списка сессий открывает `/sessions/:id`.
- На странице сессии: поле «Сообщение» и кнопка отправки (Enter отправляет, Shift+Enter переносит строку); поле «Найти в разговоре» (клавиша `/`), лупы «Мельче» и «Крупнее», мини-карта «Карта хода»; инспектор «Инспектор сессии» справа (клавиша `D`, крестик «Закрыть инспектор», кнопка «Инспектор» в строке поиска). Подпись кнопки зависит от статуса: «Отправить сообщение» при idle, «Поставить сообщение в очередь» при running (`ComposerPrimaryAction` в `components/session/SessionComposer.tsx`).

## Driving it with Playwright (verify-agent-console)

Preconditions:

- Агент `verify-agent-<nonce>` и окружение `verify-env-<nonce>` созданы (см. `agents.md`, `environments.md`).
- Режим fake: фейковая модель отвечает на `127.0.0.1:8792` (`scripts/doctor.sh`). Промпт содержит строки `Команда: <cmd>` и `VERIFY_AGENT_RUN nonce=<n>`.
- Весь путь выполняет `scripts/journey.sh`, шаги «сессия» и «ход агента».

- **Новая сессия.** Нажать ссылку «Сессии», затем `getByRole("button", { name: "Новая сессия" }).first()`. Результат: `getByRole("dialog", { name: "Новая сессия" })`. Агент и окружение подставлены по умолчанию первыми в списке.
- **Выбрать агента и окружение.** Нажать `dialog.getByRole("combobox").nth(0)`, выбрать `[data-slot="command-item"]` с id агента. Затем то же для `nth(1)` с id окружения. Результат: в тексте каждого combobox видно `<имя> (<id>)`.
- **Название и создание.** Заполнить `#session-title` значением `verify-session-<nonce>` и нажать `getByRole("button", { name: "Создать", exact: true })`. Ожидаемый результат: URL `/sessions/<id>`, h1 с названием, в шапке (`header` с h1) чипы-ссылки `a[href="/agents/<id>"]` с именем агента и `a[href="/environments/<id>"]` с именем окружения (`session.header_ui`; до переделки страницы 2026-10-16 это были бейджи с `title="Агент: …"`). `GET /v1/sessions/:id` возвращает `agent.id`, `environment_id`, `title` и `status = idle`. До первого сообщения в шапке «Ожидает», а в пустом разговоре нет «Агент работает…» (проверка `session.initial_status`: API, плашка статуса и текст страницы). Прогон 2026-10-16 (`20261016-002808`): `title` сохранён, h1 с названием (`session.title_saved` проверено; до правки консоли 2026-10-15 было `title = null`). Папки `<прогон>/data/sandboxes/<id>` ещё нет: песочница ленивая.
- **Сообщение.** До отправки открыть параллельно с консолью поток `GET /v1/sessions/:id/events/stream` (cookie браузера, `captureStream` в сценарии). Заполнить `getByRole("textbox", { name: "Сообщение" })` и нажать `getByRole("button", { name: /^(Отправить сообщение|Поставить сообщение в очередь)$/ })`. В новой сессии подпись «Отправить сообщение» (это проверка `run.ui_send_label`; регулярное выражение терпит вторую подпись, чтобы при провале ход всё равно запустился). Перед снимком дождаться, что поле ввода очистилось.
  Ожидаемый результат: в `article[data-turn-id]` реплика `[data-session-turn-prompt]` с `nonce=<n>`.
  Прогон 2026-10-16: реплика стоит в ходе сразу после отправки (`run.ui_prompt_on_send`, `screens/*-turn-prompt-visible.png`), после конца хода (`run.ui_prompt_visible`) и после перезагрузки (`run.ui_prompt_after_reload`); поток отдаёт `user.message` с маркером (`run.sse_user_message`). Как это устроено, см. в Gotchas.
- **Конец хода.** Опрашивать `GET /v1/sessions/:id/events?order=asc&limit=100` (с `page=next_page`), пока после `user.message` не появится `session.status_idle`. Результат:
  - события идут в порядке `agent.message{первое сообщение}` → `agent.tool_use{name:"bash"}` → `agent.tool_result{tool_use_id, content содержит VERIFY_OK_<n>}` → `agent.message{итоговый ответ с VERIFY_DONE_<n>}` → `session.status_idle{stop_reason.type:"end_turn"}`. Первое сообщение фейковая модель шлёт только в ходе агента (`VERIFY_AGENT_RUN`), в пробах окружения его нет;
  - `GET /v1/sessions/:id` возвращает `status = idle`;
  - в интерфейсе `article` получил `data-session-turn-status="completed"`, а `[data-session-turn-answer]` содержит `VERIFY_DONE_<n>`.
- **Ответ целиком и длительность.** В режиме fake модель в ходе 1 пишет текст перед `tool_use` (`leadText`, больше 100 символов), а итоговый ответ (`finalRunText`) состоит из строки, блока кода с `VERIFY_DONE_<n>` и строки после него. Оба текста лежат в `api/fake-model-requests.jsonl` (`reply_text` у решений `tool_use` и `final_text`).
  Ожидаемый результат:
  - `run.answer_full`: журнал хранит оба текста модели как два `agent.message`. В `[data-session-turn-answer]` есть каждая строка итогового ответа по порядку (кроме строк-ограждений блока кода; текст ответа в `api/46-turn-answer-text.txt`). Первое сообщение видно целиком в своей карточке запроса (`[data-block-kind="request"]`); до переделки страницы его прятал свёрнутый блок «Работал N с» (`[data-chat-reasoning-trigger]`, сценарий раскрывает его, только если он есть). В fake каждый текст стоит на странице ровно один раз. Строки обоих текстов не срезаны на экране (`clippedLine`: коробка самого глубокого элемента со строкой внутри предков с `overflow: hidden` или `clip` до ближайшей прокрутки; снимок `screens/*-turn-answer-full.png`);
  - `run.turn_duration`: длительность хода по журналу (`processed_at` от `user.message` до `session.status_idle`) больше секунды, поэтому на странице нет «Работал 0 с» и «Думал 0 с». Подпись «Работал N с» не больше длительности по журналу плюс 2 с. Если консоль длительность не показывает, проверяется только отсутствие «0 с».
  Если начало ответа срезано, падают обе проверки: `run.answer_full` и `run.ui_turn_done`. Срез на длину первого сообщения (105 символов) уносит `VERIFY_DONE_<n>` целиком.
- **Без расхода.** Проверка `session.ui_no_usage` собирает находки списком и падает, если в шапку или на вкладку «Сессия» вернулись токены, стоимость или бюджет. Запрещённые слова те же, что в тестах консоли: `/токен|стоимост|бюджет|нет цены|кэш|\$/i`.
  - Шапка (`header` с h1): чипы `[data-session-chip="duration"]` и `[data-session-chip="activity"]` на месте. Чипов `tokens` и `cost` нет на всей странице, в тексте шапки нет запрещённых слов.
  - Подсказки: наведение на каждый чип шапки открывает подсказку Radix, и чип получает `aria-describedby` с id копии её текста (`role="tooltip"`). Текст читается по этому id. У `duration` в подсказке «Прошло с создания …» и «Активное время …».
  - Меню: кнопка `getByRole("button", { name: "Действия", exact: true })` в шапке открывает `getByRole("menu")`. В нём пункты «Прервать», «Задать результат…», «Архивировать», пункта со словом «бюджет» нет. Сценарий снимает `screens/*-session-actions-menu.png` с открытым меню и закрывает его клавишей Escape.
  - Вкладка: `getByRole("tab", { name: "Сессия", exact: true })` в «Вкладках инспектора», затем `getByRole("tabpanel", { name: "Сессия" })`. Таблица `getByRole("table", { name: "Использование" })` держит строку «Активное время», в тексте вкладки нет запрещённых слов. На всей странице нет кнопки со словом «бюджет» в имени и текста «нет цены». Снимок `screens/*-session-tab.png`.

  Журнал `GET /v1/sessions/:id/events` (`api/47-session-page-events.json`) хранит `model_usage` у каждого `span.model_request_end`, в fake это два запроса по 10 и 5 токенов. Сценарий требует их в журнале: так видно, что токены убрала консоль, а данные есть. Чип «вход / выход» (`session.ui_header_tokens`) стоял в шапке в прогоне `20261016-060858`, владелец его отменил.
- **Инспектор.** На 1280 px `getByRole("complementary", { name: "Инспектор сессии" })` открыт сразу. Нажать «Закрыть инспектор»: панель исчезает, из адреса уходит `inspector`. Нажать `getByRole("button", { name: "Инспектор", exact: true })` в строке поиска: панель вернулась, ширина 360..720 px, в `tablist` «Вкладки инспектора» ровно вкладки «Сессия», «События», «Инструменты», «Ресурсы», «Потоки» (`session.ui_inspector`).
- **Строка вызова.** Открыть вкладку «События», затем в ходе нажать кнопку `[data-tool-call][data-event-id="<id agent.tool_use>"] button[aria-expanded]`. Результат: `[data-tool-details]` с `[data-tool-command]` (`$ команда`) и `[data-tool-output]` с `VERIFY_OK_<n>` (`run.ui_tool_card`). Вывод читается как текст: `kernel=` на своей строке, без `"type": "text"`, литералов `\n` и `\u001b` (`run.ui_tool_output_text`, текст в `api/45-tool-card-text.txt`; до правки 2026-10-15 был JSON-массив content-блоков). Длительность в строке (`formatShortDurationRu`) совпадает с разницей `processed_at` у `agent.tool_use` и `agent.tool_result` с допуском 0,25 с (`run.ui_tool_duration`).
- **Выбор события.** После клика по строке вызова в адресе `?event=<id agent.tool_use>`, в таблице `getByRole("table", { name: "События" })` строка `[role="row"][data-event-id="<id>"]` имеет `aria-selected="true"` (она одна), а регион «Выбранное событие» показывает JSON с `"id": "<id>"` (`session.ui_select_sync`).
- **События.** На вкладке «События» есть строки `user.message` и `agent.tool_use` хода с id из журнала, тип в первой ячейке. Клик по строке ставит `?event=<id>`, панель «Выбранное событие» показывает заголовок «Событие <тип>» и JSON с `"id"`, `"type"` и маркером (`nonce=<n>` или `VERIFY_OK_<n>`). JSON рисует Shiki асинхронно, сценарий ждёт строку `"id": "<id>"` (`session.ui_events`).
- **Инструменты.** Вкладка «Инструменты», `getByRole("table", { name: "Инструменты" })`: в строке `bash` «Вызовы» 1 и «Ошибки» 0, как в журнале (один `agent.tool_use` bash, `agent.tool_result` без `is_error`; `session.ui_tools`).
- **Мини-карта.** `getByRole("group", { name: "Карта хода" })`: отрезок `[data-minimap-segment][data-kind="user"]` и столько отрезков запросов, сколько `span.model_request_start` в журнале, у каждого ненулевой размер. Наведение на отрезок запроса показывает `getByTestId("minimap-card")` с именем агента (`session.ui_minimap`).
- **Поиск.** Ввести nonce в `getByRole("searchbox", { name: "Найти в разговоре" })`. Результат: `getByTestId("match-counter")` показывает `1/N` при N ≥ 2 (реплика и ответ), `CSS.highlights.get("session-search")` держит диапазоны с текстом nonce, на мини-карте есть `[data-minimap-match]` (`session.ui_search`). Поле очищается после проверки.
- **Ресурсы.** Вкладка «Ресурсы»: ссылка `/mnt/session/outputs/verify-<n>.txt` с `href` на `/v1/sessions/:id/outputs/verify-<n>.txt` (`run.ui_files`). Те же файлы видны через `GET /v1/sessions/:id/outputs`.
- **Узкий экран.** Окно 390 x 844, страница `/sessions/:id` с закрытым инспектором и `/sessions/:id?inspector=events` с нижним листом. У `document.scrollingElement` и `main` `scrollWidth` не больше `clientWidth`, прокрутка вправо до упора остаётся на нуле (`session.ui_mobile_390`). При провале в примечании стоят три самых правых элемента за краем экрана вне своих прокруток. Снимки `screens/*-session-390-*.png` идут шириной 390: `shot()` берёт ширину текущего окна.
  Прогон 2026-10-16 `20261016-070418`: проверки страницы прошли. В шапке чипы `duration` и `activity`, в меню «Действия» три пункта без бюджета, в «Использовании» одна строка «Активное время 5,6 с», хотя журнал хранит вход 20 и выход 10 токенов. ## Gotchas

- **Раскладка с 2026-10-16.** Ход рисуют карточки запросов к модели (`buildTranscriptBlocks` в `lib/session-stats.ts`, `CanonicalSessionTurn.tsx`): блока процесса «Работал N с» и `[data-chat-reasoning-trigger]` нет, вызов это строка `[data-tool-call]`, «Хронологии» и панели «Файлы сессии» нет (их заменили вкладки «События» и «Ресурсы»). Пункты ниже про блок процесса, `streamPrefixes` и анимацию раскрытия описывают прежнюю раскладку на `AgentUITurnView`; сценарий раскрывает блок, только если он есть. Без этого `run.answer_full` снимал бы ту же картинку, что `turn-done`, и падал `evidence.screens_distinct` (прогон `20261016-060057`).
- **id реплики после потока.** Консоль показывает реплику сразу с id `local-user-…` (`lib/optimistic-user-message.ts`). Ответ на POST только ставит ей `processed_at`: по локальному id её ещё ищут очередь (`system.user_message_pending`) и откат при ошибке. Когда `user.message` приходит из потока, `replaceLocalMessage` в `pages/SessionDetail.tsx` заменяет локальное событие серверным (id, время, содержимое). До правки 2026-10-16 id оставался локальным: во «Событиях» строка `user.message` несла `local-user-…`, JSON и `?event=` не совпадали с журналом, `session.ui_events` падал с «нет строки [data-event-id="sevt_…"] (user.message)» (прогон `20261016-060057`). Тесты: `pages/SessionDetail.prompt.test.tsx`, блок «реплика после user.message из потока».
- **Мини-карта в fake.** Запросы фейковой модели идут десятки миллисекунд, а `bash` около 6 с, поэтому отрезки запросов узкие (не меньше 2 px, `BAR_MIN_WIDTH_PX`), а между ними пустая дорожка: выполнение инструмента отрезка не даёт, как в образце. Наведение Playwright попадает в центр отрезка и при 2 px.
- **Подсказки Radix.** В `[data-slot="tooltip-content"]` лежат видимый текст и его копия для экранного диктора (`role="tooltip"`), поэтому `innerText` всей подсказки двоит текст. После `page.mouse.move(0, 0)` одним шагом Radix оставляет подсказку открытой: точка прыжка попадает в коридор к подсказке (grace area).
