# Правила для агентов

Эти правила читают все агенты в репозитории: Claude Code (через `CLAUDE.md`) и Codex. Правила по частям кода лежат рядом с кодом и подгружаются сами, когда работа идёт в этой папке: `platform/AGENTS.md`, `platform/apps/console/AGENTS.md`, `platform/apps/agent/AGENTS.md`.

## Проект

Конструктор агентов для бэк-офиса в духе Claude Managed Agents. `platform/` это копия Open Managed Agents с нашими правками, происхождение в `platform/ORIGIN.md`. Интерфейс по-русски, оформление DDC. Рабочая модель Qwen3.6-35B (карточка `qwen3.6-35b`, шлюз LiteLLM), её ведёт PiHarness.

Документы:

- `docs/README.md`: карта дизайна, решений D1...D40 и спек компонентов. Читать перед работой над стыком компонентов.
- `docs/plans/<волна>.md`: план волны работы. Читать перед правкой в этой волне (crud, environments, builder-agent, session-page и другие).
- `docs/verification.md`: уровни проверки. Читать перед отчётом о вехе.

## Запуск

Node 24: `eval "$(fnm env)"; fnm use 24`. Конфигурации сервера и консоли лежат в `.claude/launch.json`, в Claude Code их запускает `preview_start` по имени.

- Пара `oma-server-try` (8788) и `console-try` (5174) это пробная копия владельца с его данными. Её можно запускать и останавливать, а база `apps/main-node/data-preview/` остаётся нетронутой.
- Пара `oma-server-preview` (8787) и `console-dev` (5173) работает без входа, тенант `default`.
- Учётка для входа в пробную копию лежит в `platform/apps/main-node/data-preview/preview-account.txt`. Её содержимое остаётся в файле, в чат и отчёты оно не попадает.

## Готово значит доказано

Работа готова, когда выполнены три условия:

1. Тесты затронутого пакета зелёные. Команды по пакетам в `platform/AGENTS.md`.
2. Typecheck затронутого пакета зелёный.
3. К отчёту приложено **доказательство** с живого приложения: ответ curl для сервера, снимок экрана для консоли, прогон скилла `verify-agent-console` для хода агента и окружений.

- Тесты запускайте через `test-slot` с `--maxWorkers=2`, тяжёлые команды через `nice -n 15` и по одной: ноутбук греется, systemd-oomd убивает группу процессов при нехватке памяти. Одновременно идут не больше двух workflow.
- Каждое утверждение в отчёте несёт метку: «проверено тестом», «проверено вживую» или «не проверено» с причиной. Красный тест пишется первой строкой отчёта.
- Красный тест чините в коде. Если неверен сам тест, напишите почему и только потом меняйте его.

## Git

- Рабочая ветка `feat/agent-console`. Коммиты по-английски в стиле Conventional Commits: `feat(console): ...`, `fix(agent): ...`. Тело объясняет зачем.
- В рабочей копии лежат незакоммиченные правки других волн. В коммит идут только ваши файлы: перед коммитом сверьте `git diff --cached --stat`.
- После `git stash pop` с конфликтом файлы остаются в индексе. Сверьте `git status` и уберите чужое через `git reset`.
- Индекс и ветки трогает только координатор. Субагенты и workflow правят рабочие файлы и возвращают список изменений.
- `git push` и создание репозиториев выполняет владелец. Агент отдаёт ему готовую команду.

## Секреты и чужие процессы

- IMPORTANT: значения из `platform/.env` остаются в файле. Наличие ключа проверяется так: `grep -c '^ИМЯ=.' platform/.env`.
- Ключи и токены живут только в `.env`. Проверку утечки делает `gitleaks --redact`.
- Останавливайте процессы, которые запустили сами, по их PID. Порты 8787, 8788, 5173, 5174 и контейнеры Docker (`backoffice-*`, `qm-backoffice-*`, `mvp-test-pg`, `bo-registry`, `oma-dev-pg`) принадлежат владельцу или другим агентам.
- Отказ классификатора режима auto окончательный. Объясните владельцу, что нужно, и дайте готовую команду.

## Тексты для людей

Документы, описания скиллов, тексты консоли, отчёты и сообщения коммитов пишутся по правилам скилла unslop. Скилл лежит в `.claude/skills/unslop/SKILL.md`, копия для Codex в `.agents/skills/unslop/SKILL.md`. Перед тем как закончить текст, пройдите его по этим правилам.

Коротко о главном. Вместо тире ставьте точку или запятую. Берите простые слова. Пишите в активном залоге, одна мысль в предложении. Список пустых оборотов в правиле 23 скилла.

Механические правила проверяет `scripts/unslop-check.mjs`:

- `node scripts/unslop-check.mjs <файлы>` проверяет файлы целиком;
- `node scripts/unslop-check.mjs --diff` проверяет добавленные строки рабочей копии, запускайте перед сдачей работы;
- хук Claude Code (`.claude/settings.json`) проверяет каждую запись файла и возвращает агенту список строк;
- git pre-commit (`.githooks/pre-commit`, включается `git config core.hooksPath .githooks`) проверяет добавленные строки коммита.

Строку, где оборот нужен намеренно (цитата, пример плохого текста), помечайте `unslop-ignore`. Файл целиком пропускает метка `unslop-ignore-file` в первых строках. В коде проверяются только строки с кириллицей, то есть тексты интерфейса и русские комментарии.
