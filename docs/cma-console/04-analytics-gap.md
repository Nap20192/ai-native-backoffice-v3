Черновик 2, 16 октября 2026. Только чтение кода, ничего не менялось, тесты не запускались. Состояние кода снято около 03:40 по местному времени. Рабочая копия живая: другие агенты пишут в неё параллельно, поэтому каждое утверждение о коде проверено чтением файла в момент составления.

Сравниваются:

- наша консоль: `platform/apps/console/src` (маршруты `main.tsx`, меню `components/AppSidebar.tsx`, страницы `pages/`, стиль DDC `styles/`, правила `docs/ddc-design-system.md`);
- сервер: `platform/apps/main-node` (маршруты `/v1/*`, `/v1/oma/*`) и `platform/packages`;
- план [models-harness-analytics.md](../plans/models-harness-analytics.md). Он здесь не пересказывается, ссылки идут на его единицы: S1 (каталог моделей и цены), S3 (факты `model_calls` и API аналитики), SW (подключение), C1 (форма агента и цена в карточке модели), C2 (шапка сессии), C3 (три страницы аналитики). В репозитории есть ещё два более поздних плана, [analytics.md](../plans/analytics.md) (контракт аналитики, заменяет разделы 3.7, 3.9, 3.11 плана) и [console-parity.md](../plans/console-parity.md) (раздел 4.5). Где они меняют картину, сказано прямо, расхождения между ними в разделе 6.

Обозначения путей: `C/` это `platform/apps/console/src`, `N/` это `platform/apps/main-node/src`, `NT/` это `platform/apps/main-node/test`, `P/` это `platform`.

Размер работы, которой ещё не хватает: S это один компонент или одна ветка кода на готовых деталях; M это страница или заметный компонент на готовых деталях; L это новый тип компонента или панель с несколькими режимами. Размер считается от нуля и без вычета плана: в скобках сказано, какая единица плана это покрывает.

## 0. Коротко

1. В консоли раздела нет. Нет группы меню, маршрутов `/analytics/*`, страниц и графика. Единственное похожее место это водопад на вкладке «Хронология» сессии, он суммирует токены хода из событий (`C/components/timeline/TimelineView.tsx`, расчёт `tokens` около строки 382). В `C/components/analytics/` и `C/lib/` лежат только тесты (`analytics-format`, `analytics-params`, `axis`, `series-colors`, `analytics-api`). Код под них не написан.
2. Сервер продвинулся дальше. Библиотека `N/lib/analytics/` (12 файлов, около 580 строк, в git не добавлена) создаёт таблицы `model_calls` и `model_card_limits` при первом обращении, пишет факты, считает цены и отдаёт 9 маршрутов: `usage`, `cache`, `limits`, `limits/:card_id` (GET и PUT), `model_calls`, `model_calls/:id`, `sessions/:id`, `facets`. Рядом 12 тестов в `NT/`.
3. Библиотека не подключена. Слова «analytics» нет ни в `N/modules/node-http.ts`, ни в `N/modules/node-managed.ts` (оба файла сейчас с чужими незакоммиченными правками). Пока единица SW не сделана, `/v1/oma/analytics/*` отвечает 404 и ни один вызов модели в `model_calls` не попадает.
4. Из 15 панелей Claude для 12 данные в коде сервера есть. Для «Лимитов» это наши лимиты, которые вводит владелец, а не квоты провайдера. Для диагностики кэша данных нет, есть замена. Для оболочки раздела и узкого экрана серверная часть не нужна.
5. Основная работа в консоли. Самое тяжёлое: график (L), правая панель лимитов (L), общие компоненты раздела (инспектор, мультивыбор, индикатор, линейный график). Серверу осталось подключение (SW), починка `session.usage` и срок хранения строк.
6. Данных нет и не будет для веб-поисков, исполнения кода, времени сессий, кредитов, ключей API, участников, квот провайдера, разбивки записи кэша на 5 минут и 1 час. Для каждого пункта в разделе 4 предложена замена или честный текст пустого состояния.
7. Порядок: SW; общие компоненты (раздел 3) и «Использование»; «Журнал» с инспектором; «Стоимость»; «Кэширование»; «Лимиты».

- лимит для моделей без карточки (раздел 4);
- проверка смысла `input_tokens` у ACP-агентов и у провайдеров OpenAI: без неё доля чтения и стоимость кэша ненадёжны.

Есть у нас, а у Claude нет (оставить): фильтр и колонка harness, имена агентов вместо `agent_…`, ссылка на сессию из строки журнала, стоимость в строке запроса, плитка «Запросы без цены», статус «Ошибка» в журнале, группировка по карточке и окружению, форма лимита карточки, карточка «Агенты с низкой долей кэша».

## 5. Порядок работ

1. SW: подключить рекордер в `node-managed.ts` и маршруты в `node-http.ts`. Файлы заняты чужими правками, ждать их коммита. Сквозной тест: ход фейковой модели, потом `/usage` и `/model_calls` отдают его токены.
2. Общие компоненты (раздел 3): мультивыбор, период по UTC и «Сбросить», хук адреса, форматы, цвета рядов, `StackedBarChart`, плитки. После них «Использование» и «Стоимость» собираются на одном теле.
3. `RowInspector` и «Журнал» с карточкой запроса. Это первый потребитель инспектора.
4. «Кэширование»: линейный график и `CompositionBar`.
5. «Лимиты»: `UsageMeter`, правая панель с формой лимита, после того как решён вопрос о хранении лимитов (раздел 6).
6. Каждую страницу снять на 1280 и 390 px без горизонтальной прокрутки и сверить цифры с журналом фейковой модели скилла `verify-agent-console` (единица V1).

## 6. Где планы расходятся и что осталось непроверенным

- Хранение лимитов. analytics.md (раздел 4.5) и код держат таблицу `model_card_limits` по `card_id`. console-parity.md (раздел 4.6, S5) описывает `model_limits` по handle в миграции `0029`. Модель без карточки по первому варианту лимит иметь не может. Выбрать один вариант до подключения.
- Схема. План (раздел 3.7) просит миграцию `0028_model_calls`. Код и analytics.md создают таблицы при первом обращении (`ensureAnalyticsSchema`), в каталогах миграций последний файл `0027_tenant_invitations`. console-parity.md снова добавляет миграцию. Сейчас верно описание кода.
- Цвета рядов. План (C3) говорит «токены DDC», analytics.md берёт классы Tailwind на шкалах DDC без правки `ddc-tokens.css`. Файл `ddc-tokens.css` сейчас правят другие, так что второй путь безопаснее.
- Пик в минуту считается по концу вызова, а не по началу, как у провайдера. Для долгих вызовов Claude Code (одна строка на ход) пик грубее.
- Смысл `input_tokens` у ACP-агентов и у OpenAI не проверен. Отдаёт ли `claude-agent-acp` токены хода, неизвестно, без них строки Claude Code в аналитике нулевые, поле `usage_reported` это показывает.
- Скорость отчётов на реальных объёмах не измерена (ручной замер из плана, раздел 3.10). Тест на Postgres (`NT/analytics-model-calls.postgres.test.ts`) пропускается без `OMA_TEST_POSTGRES_URL`.
- Контраст цветов рядов в тёмной теме не измерен.
