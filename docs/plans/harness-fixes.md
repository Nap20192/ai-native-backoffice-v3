## Исправлено

Волна 2026-10-17. Тесты из `vitest.pi.config.ts`, в кавычках имя теста или блока.

- **1.** (проверено) `pi-loop.ts` `shouldRetryPiTurnAfterCompaction`: при `producedOutput` повтора нет. После первого вызова инструмента переполнение контекста роняет ход вместо сжатия. Повтор теперь решает только ошибка контекста, в том числе после вызова инструмента и после сжатия в начале хода. Тесты `pi-loop.test.ts`: «сжимает историю и повторяет ход, если контекст переполнился после вызова инструмента», «повторяет ход после переполнения и тогда, когда ход начался со сжатия». Коммит после проверки.
- **2.** (проверено) `pi-loop.ts:165`: слушатель `abort`, добавленный после отмены, не срабатывает. Отмена во время сжатия не останавливает ход. Теперь `signal.aborted` проверяется до сжатия, после него и перед `agent.continue()`. Тесты `pi-loop.test.ts`: «отмена до хода не запускает ни сжатие, ни модель», «отмена во время сжатия останавливает ход», «отмена после подписки на сигнал и до запуска агента останавливает ход». Коммит после проверки.
- **3.** (проверено) `pi-compaction.ts:187`: отклоняется только `stopReason === "error"`. Сводка, оборванная по `aborted` или `length`, становится границей сжатия. Теперь `compact()` бросает ошибку на любой `stopReason`, кроме `stop`, а `compactBeforeTurn` не пишет сводку после отмены. Тесты: `pi-compaction.test.ts` «%s не принимает сводку, завершённую по %s»; `pi-loop.test.ts` «не записывает сводку, оборванную по %s, и отвечает по полной истории», «не записывает часть сводки, если ход отменили во время запроса сводки», «не записывает сводку своей политики, если ход отменили во время сжатия». Коммит после проверки.
- **5.** `pi-loop.ts:405`: ответ из одних мыслей считается выводом, пустой `stop` вызывает сжатие. Удалённый DefaultHarness в этом случае бросал `silent_stop`. Теперь выводом считаются только текст и вызов инструмента, ход без них бросает `ModelError` `silent_stop` без сжатия. Тест `pi-loop.test.ts`: «%s со stop бросает silent_stop без сжатия». Коммит после проверки.
- **8.** `tools.ts:690`, `:772`: glob и grep разбирают только формат Cloudflare `exit=N`. На LiteBox модель получает голое `[exit 1]`, длинный вывод не обрезается. Теперь оба читают вывод через `parseExecOutput`, он понимает оба формата. Тесты `tool-exec-output.test.ts`: «parseExecOutput», «glob reads both exec formats», «grep reads both exec formats». Коммит после проверки.
- **9.** (проверено) `tools.ts:665`: `content.replace(old, new)` со строкой разворачивает `$&` и `$$` в новом тексте. Теперь edit вставляет `new_string` срезами строки и не принимает пустой `old_string`. Тест `tool-file-ops.test.ts`: «edit puts new_string in as it is». Коммит после проверки.
- **10.** (проверено) `tools.ts:688`: `pattern` glob стоит в `bash -c` как код. Через glob можно выполнить команду в обход `always_ask` на bash (только внутри VM). Теперь скрипт glob постоянный, шаблоны идут в bash позиционными аргументами, фигурные скобки раскрывает `expandBraces`. Тест `tool-file-ops.test.ts`: «glob reads the pattern only as a pattern». Коммит после проверки.
- **11.** `tools.ts:197`: `truncateResult` оставляет начало вывода, а код выхода LiteBox и ошибка сборки стоят в конце. Теперь `truncateExecResult` режет длинный вывод bash посередине, первая строка называет код выхода. Заметка `truncateResult` умещается в 50 000 знаков. Тест `tool-exec-output.test.ts`: «bash keeps the end of a long log». Коммит после проверки.
- **12.** `tools.ts:650-667`: параллельные `edit` одного файла затирают друг друга. Теперь `edit` и `write` одного файла идут по очереди через `withPathLock`. Тесты: `tool-file-ops.test.ts` «edit and write of one file in one step»; `pi-loop.test.ts` «сохраняет обе правки одного файла из одного шага». Коммит после проверки.
- **18.** `pi-loop.ts`: сообщения из журнала шли в Pi без расхода токенов, и Pi считал весь контекст по числу знаков. Теперь последнее сообщение ассистента получает расход из последнего `span.model_request_end` (`lastReplayedAssistantUsage`). Тесты `pi-loop.test.ts`: «сжимает историю, когда расход последнего ответа дошёл до порога», «отдаёт Pi расход последнего ответа, tool_search %s», «не берёт расход %s». Коммит после проверки.
- **19.** `pi-compaction.ts` `shouldCompact`: оценка Pi по 3,5 знака на токен недосчитывала русский текст, и сжатие начиналось поздно. Теперь `estimatePiRequestTokens` считает знаки вне ASCII по 2,5 на токен. Тесты: `pi-compaction.test.ts` «не недосчитывает русскую историю и не меняет счёт латиницы»; `pi-loop.test.ts` «сжимает русскую историю, которую оценка по 3,5 знака на токен недосчитывает». Коммит после проверки.
- **20.** `tools.ts` grep: команда начиналась с `set -o pipefail`, а песочница запускает её через `sh -c`, и в Debian это dash без pipefail. Каждый вызов grep на LiteBox падал с «Illegal option -o pipefail» (живой прогон 20261018-011446). Теперь труба с `head` идёт через `bash -c`, как у glob, а без лимита команда идёт прямо в sh. Тесты `tool-file-ops.test.ts`, блок «grep runs under the POSIX sh of the VM image». Коммит после проверки.
