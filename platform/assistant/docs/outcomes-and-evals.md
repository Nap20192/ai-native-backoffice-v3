# Outcome, оценка и версии агента

Изменения: подход к рубрикам и версиям промпта пересказан по ноутбукам `managed_agents` из claude-cookbooks (MIT). Названия проверок траектории взяты из promptfoo (MIT) и Google ADK (Apache-2.0), текст свой. Исходы и порядок работы судьи описаны по коду этой платформы.

## Что такое outcome

Outcome это описание результата и рубрика. После хода агента судья сверяет работу с рубрикой.

- Описание говорит, что должно получиться и где оно лежит: «Отчёт `report.md` в `/mnt/session/outputs/` с таблицей расходов по месяцам».
- Рубрика перечисляет пункты проверки. Каждый пункт можно проверить по событиям сессии или по файлу.
- `max_iterations` задаёт число попыток, по умолчанию 3, не больше 20.

Outcome задаёт человек в диалоге «Задать результат» на странице сессии. Ассистент готовит черновик через `preview_change` с видом `outcome`.

## Как работает оценка

1. Агент заканчивает ход.
2. Судья получает описание, рубрику, номер попытки и историю событий сессии.
3. Судья отвечает одним из исходов:
   - `satisfied`, всё сделано;
   - `needs_revision`, нужно доработать, с объяснением что;
   - `failed`, задачу не решить.
4. При `needs_revision` агент получает объяснение судьи и делает новый ход. Затем судья смотрит снова.
5. Если попытки кончились, а судья всё ещё просит доработку, итог `max_iterations_reached`.

Судья работает на той же модели, что и сессия. На слабой модели оценка менее надёжна, тогда рубрика должна быть проще и конкретнее.

Судья видит историю событий, а не файлы песочницы. Если пункт рубрики про файл, попросите агента в промпте или сообщении вывести ключевые строки файла в ответе.

Рубрику пишите текстом. Рубрику файлом судья на этой платформе не читает, он видит только id файла.

## Как писать рубрику

- Каждый пункт проверяем: «В таблице 12 строк, по одной на месяц», а не «таблица полная».
- По каждому пункту судья должен найти доказательство в событиях: вызов инструмента, текст ответа, вывод команды.
- Описание и рубрика не спорят о месте результата. Если описание говорит `/mnt/session/outputs/report.md`, рубрика проверяет этот же путь.
- Три-семь пунктов. Длинная рубрика размывает оценку.
- Отдельный пункт на запрет: «Агент не придумывал чисел, которых нет в исходном файле».

## Проверки траектории

Кроме рубрики, работу агента можно проверить по событиям. Названия проверок:

- инструмент вызван или не вызван;
- исход вызова инструмента;
- код выхода bash и отметка в выводе;
- файл записан;
- ответ агента содержит строку;
- сессия закончилась в покое без ошибки.

Ассистент читает события через `get_session_events` и может пройти эти проверки вручную по одной сессии.

## Версии агента и откат

- Каждая правка агента через `update_agent` даёт новую версию.
- Сессия запоминает версию агента, с которой создана. Чтобы сравнить версии, создайте две сессии с одной задачей и разными версиями.
- Если новая версия хуже, `restore_agent_version` создаёт следующую версию с полями старой.
- Меняйте одну вещь за раз: промпт, модель или инструменты. Иначе непонятно, что помогло.
