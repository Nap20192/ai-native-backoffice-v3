# Объекты платформы

Справка об объектах платформы и связях между ними. Схемы полей отдаёт `help` с нужной темой, здесь смысл и порядок.

## Агент

Агент это модель, системный промпт и инструменты. Ещё у агента бывают MCP-серверы, навыки и вызываемые агенты.

- Каждая правка агента создаёт новую версию. Старые версии остаются, к ним можно вернуться через `restore_agent_version`.
- Модель задаёт handle карточки модели. Список даёт `list` с видом `models`: поле `handle` пиши в `model` агента, поле `card_id` это id карточки, для агента оно не подходит.
- Встроенные инструменты задаёт запись `agent_toolset_20260401` в `tools`: bash, чтение и запись файлов, поиск по файлам, `web_fetch`, `web_search`. Если `tools` пуст, агент получает набор по умолчанию. Встроенный инструмент без политики работает без подтверждения.
- MCP-сервер подключается записью в `mcp_servers` и записью `mcp_toolset` в `tools`. Сервер без `mcp_toolset` и `mcp_toolset` без сервера дают ошибку 400.
- По умолчанию инструмент MCP спрашивает. Политика `always_ask` значит, что каждый вызов ждёт кнопки «Разрешить» на странице сессии. Так ведёт себя и инструмент, который появится на сервере позже. Пока вызов ждёт, сессия стоит в `idle` с `stop_reason` `requires_action`. Кнопку нажимает человек. «Отклонить» возвращает агенту отказ, и вызов не идёт.
- Без подтверждения идёт только инструмент с политикой `always_allow`. Исключение для одного инструмента задаёт запись в `configs` набора: имя инструмента и `permission_policy`. Чтение разрешай по имени, запись оставляй на подтверждении. `always_allow` в `default_config` снимает подтверждение со всего сервера.
- У старых агентов политика записана явно и сама не меняется. Консоль помечает сервер на `always_allow` словами «без подтверждения».
- Ход агента всегда ведёт встроенный цикл. Другой программы для хода нет.

Страница в консоли: `/agents` и `/agents/<id>`.

## Окружение

Окружение описывает песочницу (VM), в которой работает сессия.

- Тип `cloud`. Образ из каталога, по умолчанию стандартный.
- Сеть `unrestricted` открывает любой хост. Сеть `limited` открывает только хосты из `allowed_hosts` и то, что разрешают флаги: `allow_mcp_servers` для MCP-серверов агента, `allow_package_managers` для реестров пакетов, `allow_web_search` для поиска.
- Пакеты (`apt`, `pip`, `npm`, `cargo`, `gem`, `go`) ставятся при старте песочницы.
- Без `allow_mcp_servers` сеть `limited` выключает MCP-серверы агента.

Страница в консоли: `/environments`.

## Сессия

Сессия это разговор с агентом в своей песочнице. Ей нужны агент с версией и окружение.

- Статусы: `idle` (в покое, ждёт сообщения), `running` (идёт ход), `rescheduling` (повтор после сбоя), `terminated` (закрыта).
- Пустая сессия ничего не запускает. Ход агента начинается с первого сообщения пользователя.
- Ассистент создаёт сессию через `create_session` и отправляет первое сообщение через `send_message`. Обе записи идут через карточку подтверждения, сообщение всегда отдельной карточкой.
- Прерывание, второе сообщение, архив и удаление делает человек на `/sessions/<id>`.
- События сессии читает `get_session_events`, путь хода по шагам даёт `get_trajectory`.

## Файлы

Файл загружается один раз и дальше не меняется. Новая редакция это новый файл с новым id.

- Загрузка через `upload_file`, до 1 МБ. Текст в `utf8`, двоичные данные в `base64`.
- Чтобы агент увидел файл, его добавляют в сессию ресурсом `file`. При старте платформа копирует файл в песочницу.
- Путь в песочнице задаёт `mount_path`. Без него файл лежит в `/mnt/session/uploads/<file_id>`.
- Агент может менять копию в песочнице, файл в хранилище от этого не меняется.
- Что агент сохранил в `/mnt/session/outputs/`, остаётся после сессии. Пользователь открывает и скачивает эти файлы на вкладке «Файлы» страницы сессии. Файлы в других папках могут пропасть вместе с песочницей.
- Список загруженных файлов: `/files` в консоли, `list` с видом `files`. Текст файла читает `read_content`.

## Навык

Навык это папка с `SKILL.md` и, по желанию, скриптами и справкой. Платформа кладёт навык в песочницу агента, агент читает его, когда задача подходит под описание.

- Создание через `create_skill`, новая версия через `create_skill_version`. Правил написания навыка касается документ `writing-skills.md`.
- Навык подключается к агенту записью в `skills` агента.

Страница в консоли: `/skills`.

## Хранилище памяти

Хранилище памяти это набор текстовых записей по путям. Сессия с ресурсом `memory_store` видит хранилище в `/mnt/memory/<имя>` и может его читать и писать.

- Создание через `create_memory_store`, запись через `write_memory`: свободный путь создаёт запись, занятый путь её меняет.
- Ассистент к своим сессиям хранилища не подключает. Ресурс `memory_store` к сессии добавляет человек в консоли.

Страница в консоли: `/memory`.

## Деплоймент

Деплоймент запускает агента по расписанию: cron и часовой пояс, первые события, ресурсы, хранилища секретов.

- Ассистент создаёт деплоймент через `create_deployment` сразу на паузе.
- Запуск, пауза, снятие с паузы и архив делает человек на странице деплоймента.
- Ассистент правит только деплоймент на паузе.

## Карточка модели

Карточка модели хранит провайдера, адрес, ключ и имя модели у провайдера. Агент ссылается на карточку по handle.

- Новую карточку создаёт человек в форме на `/model-cards`. Ассистент готовит черновик через `preview_change` без ключа.
- Ассистент правит только `model`, `model_id`, `pi_config` и `is_default`. Ключ, заголовки, провайдера и адрес меняет человек.

## Хранилище секретов

Хранилище секретов держит учётные данные для MCP-серверов и переменных окружения. Значения секретов ассистент не видит и не задаёт. Ссылку на форму даёт `request_secret`, страница `/vaults`.

## Outcome и оценка

Outcome это описание результата и рубрика, по которой судья проверяет работу агента в сессии.

- Outcome задаёт человек в диалоге «Задать результат» на `/sessions/<id>`. Ассистент готовит черновик через `preview_change` с видом `outcome`.
- После хода агента судья читает описание, рубрику и историю сессии и отвечает `satisfied`, `needs_revision` или `failed`.
- При `needs_revision` агент получает объяснение судьи и делает ещё один ход. Число попыток задаёт `max_iterations`, по умолчанию 3, не больше 20. Если попытки кончились, итог `max_iterations_reached`.
- Судья работает на модели самой сессии. Слабая модель судит слабее.
- Рубрику пишите текстом. Рубрику файлом судья на этой платформе не читает, он видит только id файла.

Подробнее в `outcomes-and-evals.md`.
